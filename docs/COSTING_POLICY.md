# سياسة تكلفة المخزون (Inventory Costing Policy)

**المرجع التدقيقي:** H-4
**التاريخ:** 2026-06-14

## 1. الطريقة المعتمدة

يعتمد النظام طريقة **المتوسط المرجّح المتحرّك (AVCO / Weighted Average Cost)** المسموح بها صراحةً في **IAS 2 §25**.

- تُحتسب التكلفة عند كل **استلام شراء** في `PurchaseItem::created()`:
  `new_cost = (old_qty × old_cost + new_qty × new_cost) / (old_qty + new_qty)`
- تُحفظ كل تغييرة في `cost_price_histories` (شفافية وأثر تدقيق).
- التحديث محميّ بقفل تزامن (`lockForUpdate`) لمنع تعارض العمليات المتزامنة.

## 2. النطاق: التكلفة على مستوى المنشأة (Entity-level)

`products.cost_price` قيمة **واحدة على مستوى المنشأة** لكل صنف، بينما تُمسَك **الكميات لكل مخزن** (`stock_levels`).

**القرار:** تُعتمد تكلفة AVCO على مستوى المنشأة (لا لكل مخزن). هذا متوافق مع IAS 2 (الذي يسمح بمتوسط مرجّح على مستوى المنشأة) ويبسّط الترحيل.

**الأثر على التقارير:** تقارير التقييم لكل مخزن (كمية المخزن × التكلفة العالمية) هي **تقريب** — لا تعكس فروق تكلفة محتملة بين المواقع. تقرير قيمة المخزون الكلي على مستوى المنشأة **دقيق**.

## 3. متى يلزم الترقية لتكلفة لكل مخزن؟

يُنتقل إلى **تكلفة لكل مخزن** فقط إذا:
- اختلفت تكاليف التوريد جوهريًا بين المواقع/الفروع، **و**
- تطلّبت التقارير المالية الفرعية (لكل فرع) دقة تقييم على مستوى الموقع.

عندها: نقل التكلفة إلى `stock_levels.cost_price` واحتساب AVCO لكل (صنف، مخزن)، وتعديل خدمات التقييم والترحيل وفقًا لذلك (تغيير معماري — يُجدوَل كمشروع منفصل).

## 4. ملاحظات

- **FIFO** متاح كتقرير تحليلي فقط (`reports.fifo-valuation`) للمقارنة، دون تغيير المحرّك المعتمد (AVCO).
- **هبوط القيمة (IAS 2):** يُقاس المخزون لاحقًا بأقل من التكلفة وصافي القيمة البيعية عبر تقرير `reports.inventory-valuation`، ويُرحَّل قيد الهبوط يدويًا بعد المراجعة.
