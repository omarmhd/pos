### 1.3 فجوة جديدة مكتشفة خلال هذا الفحص العميق

**الفجوة #4 (جديدة): مرتجع البيع يُعيد تكلفة البضاعة المباعة (COGS) بسعر التكلفة *الحالي*، لا بسعر تكلفة *وقت البيع الأصلي*.**

- **الموقع:** `SaleReturnController.php:107` → `'cost_price' => $product->cost_price` (القيمة الحالية في جدول `products`، بعد أي AVCO لاحق).
- **الاستهلاك:** `LedgerPostingService.php:302-305` → `$cogs = Σ(quantity × cost_price)` المخزَّن في `SaleReturnItem`.
- **الأثر العددي:** انظر القسم 3 (Reconciliation Engine) — سيناريو AVCO يُثبت انحرافًا بقيمة **+50 ج.م** في حساب 1300/5000 عند وجود شراء جديد بسعر مختلف بين البيع والمرتجع.

### Level 2 — تدفق دورة "بيع → مرتجع" مع التحقق المحاسبي (يُفصَّل عدديًا في القسم 3)

```
SaleController::store()
   → SaleItem (cost_price = products.cost_price وقت البيع)   ← Snapshot صحيح هنا
   → WarehouseService::out()  → stock_levels -= qty ; products.quantity = SUM(stock_levels)
   → LedgerPostingService::postSale()
        Dr 1000/1200 (Cash/AR)        = sale_total
        Cr 4000 (Sales)               = sale_total
        Dr 5000 (COGS)                = Σ(qty × SaleItem.cost_price)   ← يستخدم Snapshot الصحيح
        Cr 1300 (Inventory)           = نفس القيمة

SaleReturnController::store()
   → SaleReturnItem (cost_price = products.cost_price *الحالي وقت المرتجع*)  ← ⚠️ ليس Snapshot من SaleItem
   → WarehouseService::in()  → stock_levels += qty ; products.quantity = SUM(stock_levels)
   → LedgerPostingService::postSaleReturn()
        Dr 4200 (Sales Returns)       = return_total
        Cr 1000/1200 (Cash/AR)        = return_total
        Dr 1300 (Inventory)           = Σ(qty × SaleReturnItem.cost_price)  ← ⚠️ قد يختلف عن القيمة الأصلية
        Cr 5000 (COGS)                = نفس القيمة
```

## 3. محرك التسوية (Reconciliation Engine) — بأرقام حقيقية

### 3.1 السيناريو الموسَّع (يبني على القسم 7 من التقرير الأصلي + شراء إضافي بسعر مختلف)

| # | الحركة | التفاصيل | القيد المحاسبي |
|---|---|---|---|
| 1 | شراء 100 وحدة @ 10 ج.م (آجل) | AVCO: `cost_price = 10` (لا رصيد سابق) | Dr 1300=1000 / Cr 2000=1000 |
| 2 | بيع 30 وحدة @ 15 ج.م نقدًا | `SaleItem.cost_price = 10` (Snapshot وقت البيع) | Dr 1000=450 / Cr 4000=450 — و — Dr 5000=300 / Cr 1300=300 |
| 3 | **شراء جديد: 50 وحدة @ 14 ج.م (آجل)** *(حركة إضافية لهذا الملحق)* | AVCO الجديد = `((70×10) + (50×14)) / 120 = (700+700)/120 = 11.6667` → `products.cost_price = 11.6667` | Dr 1300=700 / Cr 2000=700 |
| 4 | مرتجع 10 وحدات من البيع في الخطوة 2 (نقدًا) | **الكود الحالي**: `SaleReturnItem.cost_price = products.cost_price الحالي = 11.6667` (وليس 10 الأصلي) | Dr 4200=150 / Cr 1000=150 — و — Dr 1300 = 10×11.6667=**116.67** / Cr 5000=**116.67** |
| 5 | دفع 1000 ج.م للمورد | تسوية AP جزئية | Dr 2000=1000 / Cr 1000=1000 |
| 6 | إقفال الوردية — فرق نقدي = عجز 5 ج.م | يُرحَّل على الحساب الجديد 6530 (بدل 6520 المتصادم سابقًا) | Dr 6530=5 / Cr 1000=5 |

| **حساب 4200 (Sales Returns)** | 150 | 150 | 0 ✅ |
