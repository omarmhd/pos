# سياسة تصنيف المخزون: الأصناف مقابل المنتجات المصنّعة (IAS 2 §37)

**الطلب:** فصل "الأصناف" عن "المنتجات" (المصنّعة صناعيًا) كما يطلب المحاسب.
**القرار:** اعتماد تصنيف مخزون وفق IAS 2 §37 عبر **فئات + حسابات مخزون منفصلة**، لا عبر جداول قواعد بيانات منفصلة.
**التاريخ:** 2026-06-14

## 1. الدراسة المحاسبية

يصنّف معيار IAS 2 §37 المخزون عادةً إلى: بضاعة تجارية، مواد خام، إنتاج تحت التشغيل، وبضاعة تامة الصنع. المنشأة التي **تشتري وتُصنّع** (سوبرماركت + مخبوزات/تجهيز مثلاً) يلزمها التمييز بين:

| الفئة | الوصف | حساب المخزون |
|------|-------|--------------|
| **بضاعة تجارية (Merchandise)** | تُشترى وتُباع كما هي | مخزون بضاعة (1300) |
| **مواد خام (Raw Materials)** | تُشترى وتُستهلك في التصنيع | مخزون مواد خام (1310) |
| **منتج تام الصنع (Finished Goods)** | يُصنَّع داخليًا ويُباع | مخزون منتجات تامة (1320) |
| **خدمة (Service)** | بلا مخزون | — |

## 2. لماذا فئات + حسابات، لا جداول منفصلة؟

التمييز في IAS 2 **محاسبي/عرضي** (حسابات وقوائم)، لا بنيوي. فصل الجداول (Items vs Products) إعادة هيكلة ضخمة تمسّ POS/البيع/الشراء/التقارير وعالية الخطر دون فائدة محاسبية إضافية. **الصحيح والأسلم:** جدول `products` واحد + **حقل فئة** + **حساب مخزون مستقل لكل فئة**.

## 3. الأساس موجود في النظام ✅

- لكل صنف حقلان: `inventory_account_id` و`cogs_account_id` — أي يمكن ربط حساب مخزون مختلف لكل فئة.
- **مستند التصنيع (`Assembly`) يُرحّل بالفعل بشكل صحيح:**
  ```
  مدين: مخزون المنتج التام (product.inventory_account_id)   = تكلفة الإنتاج
  دائن: مخزون كل مكوّن مستهلَك (component.inventory_account_id) = تكلفته
  ```
  أي تحويل التكلفة من المواد الخام إلى المنتج التام — **محاسبيًا سليم**.

**الناقص فقط:** تصنيف الأصناف صراحةً، وربط حسابات المخزون الثلاثة، وفصل الشاشات.

## 4. التدفق المحاسبي الصحيح (بعد الفصل)

1. شراء مواد خام: مدين **مخزون مواد خام (1310)** / دائن موردون.
2. شراء بضاعة تجارية: مدين **مخزون بضاعة (1300)** / دائن موردون.
3. التصنيع: مدين **مخزون منتجات تامة (1320)** / دائن **مخزون مواد خام (1310)** (بتكلفة المواد المستهلكة).
4. بيع منتج مصنّع: مدين تكلفة مبيعات / دائن **مخزون منتجات تامة (1320)**.
5. بيع بضاعة: مدين تكلفة مبيعات / دائن **مخزون بضاعة (1300)**.

## 5. خريطة الفئة ↔ نوع الصنف الحالي

| الفئة الجديدة (`product_class`) | يقابل `product_type` الحالي |
|------|------|
| merchandise (بضاعة تجارية) | goods (افتراضي) |
| raw_material (مادة خام) | goods (يُستخدم كمكوّن) |
| manufactured (منتج تام الصنع) | bundle (تجميعي) |
| service (خدمة) | service |

> `product_type` يبقى يقود **السلوك** (تجميعي=يُصنّع، خدمة=بلا مخزون)، و`product_class` يضيف **التصنيف المحاسبي + فصل الشاشات** دون كسر المنطق القائم.

## 6. ما سيُنفَّذ (إضافي وآمن)

1. حقل `product_class` على `products` + تعبئة تلقائية من النوع الحالي.
2. بذر ثلاثة حسابات مخزون (1300/1310/1320) + مفاتيح إعدادات + إضافتها لخريطة الحسابات.
3. **ربط تلقائي** لحساب المخزون حسب الفئة عند الحفظ (إن لم يُحدَّد يدويًا) — فيصبح الترحيل صحيحًا تلقائيًا.
4. فصل العرض: شاشة **"الأصناف"** (بضاعة + مواد خام) مقابل **"المنتجات (المصنّعة)"** عبر فلتر الفئة.
5. التصنيع: لا تغيير — يُرحّل صحيحًا أصلًا.
